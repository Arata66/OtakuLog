# API 权限闭环实施计划

> 执行方式：使用 executing-plans 在当前对话逐项执行，先测试复现，再最小修复。用户已授权开始，不另开对话或分派子代理。

**目标：** 私人 API 需要登录，写操作校验 CSRF，登录退出与已有页面可用，Service Worker 不保留私人 API 响应。

**架构：** 保留表单登录和单用户身份。使用 Spring Security 默认会话 CSRF 与 Thymeleaf 注入的令牌，通过页面元标签向统一请求函数传递令牌。安全过滤器为 API 返回统一 JSON 错误，普通页面维持登录跳转。

**技术：** Java 17、Spring Security、MockMvc、JUnit 5、原生 JS、Node 内置测试运行器。

## 文件职责

| 文件 | 操作与职责 |
|---|---|
| `src/main/java/com/otakulog/config/SecurityConfig.java` | 收紧白名单、开启 CSRF、处理 API 401/403 |
| `src/main/resources/templates/anime.html` | 输出 CSRF 元标签，保留带令牌的退出表单 |
| `src/main/resources/static/js/anime-app.js` | 写请求携带令牌，会话过期引导重新登录 |

| `src/test/js/security.test.cjs` | 验证前端请求令牌和缓存安全行为 |
| `README.md` | 补充认证、CSRF、PWA 缓存限制和测试命令 |

测试核心断言：

```java

    .andExpect(status().isUnauthorized())
    .andExpect(jsonPath("$.code").value(401));
mvc.perform(post("/api/anime/1/next-episode").with(user("test")))
    .andExpect(status().isForbidden())
    .andExpect(jsonPath("$.code").value(403));
```

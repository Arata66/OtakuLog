# 可解释统计设计与实施计划

日期：2026-10-08。承接已授权的第一阶段 E，继续使用现有独立实施工作区，主仓库不重复实现。

## 目标与取舍

年报分别回答“这一年完成了多少作品”和“这一年有明确日期的观看记录有多少集”。保留原接口和四项统计卡，不把完成作品的总集数当成实际年度观看量，不按创建时间或进度推算缺失日期。

相较于继续沿用完成作品集数，逐集日期能正确覆盖跨年观看与未完成作品；相较于把所有历史日期都当作确定事实，来源分开能避免将 V5 历史估算伪装成真实观看。本阶段选择逐集统计并展示数据覆盖范围，不修改历史日期或引入新的估算算法。

## 统计口径

- `totalWatched` 继续表示当年完成作品数：当前状态为 FINISHED 且 endDate 在该年。
- `totalEpisodes` 改为当年日期明确且来源为 WATCHED、MANUAL、IMPORT 的逐集记录数，覆盖全部作品状态；`watchedAnimeCount` 为其中不同作品数。
- 来源为 LEGACY 且日期落在该年的记录单列 `legacyDatedEpisodes`，可能含旧估算，不并入明确日期观看量。日期未知的记录不归入任何年。
- `undatedEpisodeRecords`、`missingEpisodeRecords`、`undatedFinishedAnimeCount` 是全库数据覆盖提示：分别表示日期未知记录、已有进度缺逐集记录、完成日期未知的已完成作品。前端明确标记全库，不能理解为该年漏计量。
- 评分、TOP 榜和标签分布继续以当年完成作品为范围。年/月均分仅纳入有效评分 0 < score <= 10，空或 0 为未评分；返回已评分数量，无评分时 UI 显示“未评分”，不显示为零分。
- `watchingHours` 按明确日期观看集数 × 24 / 60 估算，增加 `minutesPerEpisode=24` 与 `watchingHoursEstimated=true`。月份按完成日期归完成数，按逐集日期归观看数；每年固定 12 个月。
- 年份限制为 1000–9999，非法请求返回 400。读取使用同一只读事务快照，报告不写入数据库。

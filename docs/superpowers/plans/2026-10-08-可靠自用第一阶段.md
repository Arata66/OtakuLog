# 可靠自用第一阶段路线与验收

日期：2026-10-08。

## 授权与执行方式

用户确认近期以自用发展，长期兼顾作品集和公开产品，并授权直接决定计划与开始顺序。

在独立工作区和 `Arata66/reliable-self-use` 分支执行。每个小节独立测试、提交和推送；推送失败时遵循 AGENTS.md 停止后续修改。

本轮先完成第一小节“登录与 API 权限闭环”。其余小节按下列依赖顺序推进，涉及数据格式和迁移的内容在各自实施前写独立详细方案，避免在一次大改动里混合验证。

## 总目标

保证私人数据只能由登录用户访问，部署步骤可复现，备份可恢复完整记录，观看写入原子化，统计含义明确。

不扩展多用户、重看轮次、离线写入、推荐算法或前端框架重写。

## 小节与交付

| 顺序 | 小节 | 核心改动 | 验收 |
|---|---|---|---|
| A | 登录与 API 权限闭环 | 收紧匿名路径、恢复 CSRF、适配前端、清理私人缓存 | 匿名读写 API 返回 JSON 401；登录后可读；写入需合法 CSRF；登录退出正常；离线不返回私人缓存 |
| B | 可复现部署 | 统一 JDBC 地址和数据库名、MySQL 就绪检查、环境变量与操作说明 | 空库初始化成功；数据库延迟就绪时应用可启动；重启后数据存在；旧库升级可验证 |
| C | 观看写入一致性 | 统一服务事务、进度状态完成日期规则、补录来源与日期语义 | 写入中途异常时全部回滚；进退集和批量状态行为一致；导入不伪装真实观看日期 |
| D | 完整备份恢复 | 版本化备份、逐集记录、标签、分组关系、兼容旧格式、预览与原子导入 | 空库恢复后一致；重复导入幂等；非法关联不部分写入；旧格式不覆盖真实观看日期 |
| E | 可解释统计 | 完成作品量与实际观看量分开，修正未评分均分，标记估算时长 | 跨年观看按实际日期计入；未完成作品实际观看不漏计；未评分不拉低均分；估算有明确标识 |

C 在 D 前实施，因为完整恢复需要确定观看事件和日期的业务含义。B 的 Docker/MySQL 验证必须使用隔离数据库或新卷，不操作现有自用数据库。

## B 的执行边界

- 涉及 `docker-compose.yml`、`src/main/resources/application.properties`、`README.md` 和部署验证说明。
- 容器通过 `SPRING_DATASOURCE_URL` 指向 `mysql:3306/otakulog`，保留本地直连配置可用。
- MySQL 配置健康检查，应用依赖健康状态；管理员凭据可通过环境变量传入。
- 空库和从旧版本升级分别验证，不能用 H2 自动建表证明 Flyway 正确。
- 若宿主没有 Docker，只能报告静态配置检查通过，不能宣称部署验证完成。

## C 的执行边界

- 涉及 `AnimeServiceImpl`、`EpisodeRecord`、相关仓储和新的非测试事务行为用例。
- 添加、进退集、状态变更和导入的多表写入必须在服务事务内完成。
- 保留用户主动填写的历史日期，区分真实观看与无准确日期的导入补录。
- 将完成状态、当前集数和完成日期的规则写成行为用例；异常注入验证真实事务回滚。
- 如需字段迁移，仅增加新的 Flyway 版本，不修改已执行迁移。

## D 的执行边界

- 抽取独立备份服务与 DTO，JSON 顶层包含格式版本、番剧、标签、分组、关联和观看记录。
- 备份内的本地 ID 只作引用；导入时建立映射，不把其他数据库的 ID 当成本库 ID。
- 默认合并导入；名称与 Bangumi ID 身份冲突先预览并拒绝静默覆盖。
- 全量结构与关联校验成功后原子写入；保存真实观看日期；旧版数组导入不能删除已有真实日期。
- WebDAV 复用相同的完整备份格式；本阶段不宣称解决双向同步冲突。
- 导出、空库恢复、重复恢复、非法关联、旧格式兼容和中途回滚均需行为测试。

## E 的执行边界

- 涉及年度报告服务、DTO、前端展示及报告测试。
- 完成作品数按完成日期；年度观看集数按逐集观看日期，导入未知日期单独说明。
- 均分仅以有评分作品作为分母，月度和年度使用一致规则。
- 每集 24 分钟保留为估算，界面明确写明，不显示为精确观看时长。
- 使用跨年作品、当年未完成作品、未评分作品和历史补录构造验收样本。

## 统一质量门禁

在 Java 17 下执行：

```powershell
mvn -o -q -DskipTests compile
mvn -o -q test
node --check src/main/resources/static/js/anime-app.js
node --check src/main/resources/static/sw.js
git diff --check
```

新增前端行为测试时使用 Node 内置测试运行器，不引入前端构建工具。每小节检查 README、相关文档和项目记忆；结论不写成 AGENTS.md 历史日志。

## A 的验证结果

- 修复前：27 个安全用例中 17 个断言失败，复现匿名访问和 CSRF 关闭；前端 15 个用例中 11 个失败，复现令牌与缓存问题。
- 修复后：Java 17 干净编译通过；71 个 Java 用例和 16 个 Node 行为用例全部通过。
- 全部 4 个 JS 语法检查和空白检查通过。
- 真实页面令牌、表单登录、退出后会话失效通过 MockMvc 验证；没有执行浏览器端到端或生产部署。
- 私人 API 不作离线缓存，作为权限边界的一部分交付；没有增加离线私人数据访问。

# 日常追番入口与进度反馈实施计划

用户已授权决定顺序并继续，沿用可靠自用工作区和分支，单代理实施。设计沿用原生 JS、Outfit 字体及现有主题变量，不重做首页。

## 设计与边界

采用首页紧凑双栏列表，继续观看为主、今日放送参考为辅；手机单列。相比新增独立页面或大面积封面墙，直接缩短首页记进度路径，保留原有筛选与列表。

只读 `GET /api/watch/daily` 返回服务器日期、星期、可继续追中总数、今日放送参考总数和两组各最多 6 部的列表。继续观看仅包含 WATCHING、非负且未到总集数的有效进度，按最近明确逐集日期降序、手动排序、名称和 ID 稳定排列；日期缺失或仅 LEGACY 时明确显示未知。最近日期排除未来记录，不用资料更新时间推测观看。今日参考仅匹配保存的放送日，排除尚未开播的作品，不请求 Bangumi 或写回放送日，不宣称该集已上线。

日常模块不依赖列表筛选或分页；使用完整作品 VO 保障详情缓存。刷新失败保留旧列表并标注过期，不让旧请求覆盖新状态。首次加载失败有重试、空列表有引导。

进退集继续复用原有事务 API，抽成 watch-actions.js。单作品请求进行中禁用页面上相同作品的进退集按钮，跨作品允许独立操作。成功显示具体集数、自动完成或退至计划，并刷新日常入口、列表、统计、热力图及当前详情；失败不推进本地进度、不自动重试，网络结果不明时提示刷新核对。

详情不整体重建以保留焦点与日期草稿；更新进度/状态字段，逐集列表无草稿时刷新、有草稿时保留输入并提示重载。不会点击自用库的写入按钮验收；写入流程使用隔离库和 Node 行为测试。

## 验收重点

打开首页不会写数据库，不会把放送日当作可看集数；筛选列表不影响日常模块。一次待响应期间的重复点击只发一次请求，成功使用服务端返回进度，失败不在本地假推进。详情草稿和过期响应保护保留。网络中断不保证服务器未写入，前端必须提示核对，不能自动重试；不同窗口间不提供幂等请求承诺。

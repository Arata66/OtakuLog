# 观看写入一致性设计与实施

日期：2026-10-08。承接第一阶段 C，用户已授权决定顺序并继续实施。

## 取舍与规则

仅加事务不能修复单条、批量、导入的规则差异；本节同时抽取观看规则并补齐日期来源。完整备份格式与年度统计留到 D、E。

- 新增、编辑、进退集、状态切换、旧格式导入在服务事务内完成，多表失败全部回滚。
- 编辑弹窗把资料和状态合并为一次请求，`AnimeUpdateDTO.status` 为可选字段；旧客户端不传时保留既有行为。状态失败时整张表单回滚。
- 进退集、编辑和状态切换锁定番剧行；批量操作按 ID 排序，使用同一状态规则。
- 计划从 0 集开始；追中默认记录第 1 集；下一集到总集数自动完成；上一集允许退至 0，并回到计划。越界不写入。
- 标记完成同步总集数，保留已有完成日期；缺失逐集记录只补未知日期，不假定整部都在今天观看。
- 追中、搁置保留进度和逐集历史，清除完成日期；有进度时直接改计划会拒绝，避免静默清空记录。
- 编辑总集数不能小于当前进度；已完成作品增加总集数后恢复追中并清除完成日期。
- 新增时保留主动填写的观看日期和完成日期；旧番未填日期不补成今天。
- JSON/Bangumi 旧格式只有进度，无逐集日期，补录使用空观看日期与导入来源。JSON 合并不得降低已有进度，不删除或覆盖既有逐集日期；重复名称复用同一条番剧。
- `EpisodeRecord` 新增来源：`WATCHED`（本次观看）、`MANUAL`（手动补录）、`IMPORT`（导入）、`LEGACY`（来源不可考的已有记录）；观看日期允许为空。V9 为已有记录标记 LEGACY，不重写历史日期。
- 热力图仅聚合已知日期；有逐集记录但日期都未知或不在窗口内时，不回退生成估算日期。无逐集记录的历史数据仍保留旧兼容逻辑，后续 E 再明确展示口径。

## 验收边界

不重写旧 V5 估算日期，不猜测历史记录来源；旧 JSON 仍不是完整备份。有已有进度的旧格式导入发生倒退时拒绝整次操作，完整冲突预览由 D 处理。

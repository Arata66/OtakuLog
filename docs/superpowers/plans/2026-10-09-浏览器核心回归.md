# 浏览器核心回归实施计划

用户已授权决定顺序并继续，采用当前会话逐项实施。延续可靠自用工作区；质量检查、开发分支CI通过后自动合并main并推送，核对main CI。

## 目标与取舍

用真实Chromium验证原生确认弹窗、页面草稿保护、最后一集与退集联动，以及两个独立登录窗口的快照冲突。沿用随机演示库，每个用例启动自己的应用和虚构样例，正常或测试失败时均停止持有的Java进程并核对本次库已清理，不接受外部地址或自用8080作为测试目标。

选择Playwright开发依赖及原生JS测试，不引入前端构建工具。现有Node模拟DOM测试保留，手工浏览器验收也保留其边界；它们无法单独证明原生弹窗和双窗口交互。浏览器测试通过真实表单登录、点击与输入执行业务操作，真实HTTP只用于核对持久化结果，不模拟业务API。

为避免CDN波动，浏览器路由用锁定的本地开发依赖提供页面已有的Chart.js、Sortable、marked和DOMPurify资源；其他外部请求阻止。Service Worker在此套测试中禁用，它已有独立行为测试。图标/外部资源加载、整体视觉、其他浏览器和Docker容器部署不因此宣称验收通过。

## 文件职责

- `package.json`、`package-lock.json`：锁定浏览器测试及上述页面资源开发依赖，提供`npm run test:e2e`，应用运行不依赖npm。
- `playwright.config.cjs`：Chromium、单worker、失败截图和trace，报告输出到忽略目录，CI不自动重试掩盖失败。
- `src/test/browser/fixtures.cjs`：复用`runDemo`，分配空闲回环端口，每用例独立库与应用；浏览器请求隔离、登录、关闭与数据库清理核对。
- `src/test/browser/core-flow.spec.cjs`：用户操作及持久化断言，来源核对/清空日期/丢弃草稿的取消，完成/退集联动，双窗口409与重载核对。
- `.github/workflows/ci.yml`：安装锁定依赖与Chromium，运行浏览器回归，保存失败诊断及报告。
- `.gitignore`、README、演示说明、阶段入口与记忆：运行命令、验证边界和完成状态。

## 本地验收结果（2026-10-09）

五个Chromium用例全通过，不自动重试。对确认取消与409前端分支做临时路由故障注入，分别捕获意外PUT和仍启用的保存按钮；两个失败均为预期业务断言。新增的第二窗口使用独立登录上下文，诊断由Playwright统一记录，取消重复启动trace的配置冲突。

最终Java178、Node69、脚本语法13全部通过，无测试跳过。自用预览登录、导出、只读恢复预览、年报、日常入口、逐集和匿名拒绝检查通过。读取的当前业务库为12部作品、70条逐集记录（61 LEGACY/8 MANUAL/1 WATCHED）；新作品审计时间早于本次浏览器写入验收，未有虚构演示名称。旧11/62只是先前快照，不自动回滚当前数据；本节所有验收写入均在随机演示库。

$env:JAVA_HOME='C:\Program Files\Java\jdk-17.0.18'

mvn clean verify
npm ci
npx playwright install chromium
npm run test:e2e

每个用例须验证界面可见结果及真实记录，取消操作不发送对应写请求；双窗口第一个保存成功，第二个保留草稿并显示冲突，重载确认前取消保持草稿，确认后显示已持久化的新值。失败诊断不当成通过，强制杀进程仍有残留库边界。

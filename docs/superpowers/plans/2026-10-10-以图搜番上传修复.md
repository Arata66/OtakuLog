# 以图搜番上传修复与外部联动核对

日期：2026-10-10。承接已完成的可靠自用和外观优化，按既有授权继续外部服务验收。

## 问题与范围

现有以图搜番把截图编码为 Base64 data URI 放进 GET 查询参数。普通截图会形成很长的请求地址，也不符合官方本地图片上传协议。官方支持 POST `/search`，图片原始字节放进请求体，媒体类型使用图片类型；未提供类型时支持 `application/octet-stream`。

本节只修正服务端图片上传，保留本地 multipart 接口和候选结果字段。Bangumi 搜索、详情、剧集、日历和排行榜只读核对，不向自用库执行测试写入，不配置或写入真实 WebDAV。

参考：[trace.moe 官方接口](https://soruly.github.io/trace.moe-api/#/docs)。Docker 引擎管道仍不存在，容器构建、健康依赖和卷重启仍待验收。

## 实施与验收

1. 用 64 KiB 虚构字节重现旧服务的请求方式错误；覆盖候选解析、前五个候选、空结果、额度耗尽和连接失败。
2. 改用 POST 原始字节上传，缺少媒体类型时回退二进制类型，不增加新业务字段或依赖。
3. 运行 Java 17 编译、完整 Java/MySQL 测试、Node 和脚本语法及空白检查；在临时隔离演示中核对本地上传入口，外部可用性单独记录。
4. 同步使用文档与记忆；提交推送开发分支，CI 通过后同步并合并 main，核对主分支 CI。
5. 启动当前开发预览并检查登录页面和只读业务接口。

## 本地结果

- 修复前五个新增用例均因 GET 图片查询参数不符合上传约定而失败；改为 POST 后五个用例通过。
- Java 17 离线干净构建与 183 个 Java 用例通过，含 9 个真实 MySQL 用例，无失败或跳过；69 个 Node 用例、16 个脚本语法和空白检查通过。
- 独立只读代码审查未发现合并前必修问题；已排除构建产生的已跟踪 `target/` 改动，不把旧构建产物混入提交。
- 随机隔离演示中的六个 Bangumi 只读入口及真实 trace.moe 图片上传均返回 200。官方公开演示图返回五个候选、最高相似度 99%；业务备份内容未变且本次演示库已清理。导出时间按元数据排除，不能误判业务变化。
- 外部结果与剩余边界见 `docs/以图搜番与外部服务.md`；远程 CI 与合并结果在推送后核对并写入项目接续记忆。

## 一、产品目标与首版范围

用户已确认独立桌面体验、本地存储、免注册登录、可选自备 AI 密钥和 GitHub 下载分发。以下系统支持范围、备份保留策略和关闭行为属于本计划建议，实施时按阶段验收。

- 首版面向 Windows x64，优先验证 Windows 11；Windows 10 22H2 在真实环境通过后才列入支持范围。首版不承诺 Windows 7、ARM64、macOS 或 Linux。
- 打开独立软件窗口，不要求用户先启动命令行、数据库或浏览器。
- 不建设注册、云账号、邮箱验证或找回密码；默认使用一个本地资料库。
- 番剧、进度、逐集日期、感想、确认观点、推荐条件、反馈和非秘密调用历史保存在本机。
- AI 默认关闭，可以完全跳过；首版只支持已集成的 DeepSeek 服务。其他供应商、自定义地址和本地模型另立兼容阶段。
- AI 密钥由用户自行提供，软件不提供共享额度；发送前说明所选文本会交给供应商处理及可能产生费用。
- GitHub Releases 提供免安装 exe，并提供安装版；解压运行包作为排障与分发补充。
- 延续现有完整备份与恢复规则。手机随时访问、自动双向同步、多人资料库、插件系统、开机自启和托盘常驻不进入首版。
- 本轮已获实施授权；开发与写入验收只用隔离资料，不迁移或试写自用数据库，候选验收前不创建公开Release。

## 三、技术路线比较与推荐

| 路线 | 收益 | 成本与结论 |
|---|---|---|
| Electron + 现有 Java | 继续复用现有网页；内置网页运行环境；可生成单文件免安装入口和安装器 | 包体和常驻资源增加，还需要维护 Java 子进程；推荐首版采用，先实测整体资源 |
| Tauri + 现有 Java | 可使用系统 WebView，具备原生窗口与子进程集成能力 | 增加 Rust 工具链；Windows 还要处理 WebView2 缺失及离线分发，不作为首版默认路线 |
| Java 启动器 + 外部浏览器 | 改动较少，能用 jpackage 分发运行环境 | 保留浏览器使用方式，无法直接满足独立软件窗口目标，作为内部调试入口保留 |

Tauri 的安装器可下载或携带 WebView2，离线与固定运行时模式会增加分发体积，因此不能仅依据壳程序大小判断整体包体，见[官方 Windows 分发说明](https://v2.tauri.app/distribute/windows-installer/)。Electron 的免安装目标已有[官方打包工具说明](https://www.electron.build/v26/docs/nsis/#portable)。选 Electron 是本项目结合现有代码的工程判断，不代表所有桌面程序都应采用它。

数据库优先验证 H2 文件模式：它可在 Java 进程内直接持久化文件，支持事务与行锁，见[H2 官方功能说明](https://www.h2database.com/html/features.html)。SQLite 的写入和锁模型需要额外适配，本阶段不同时引入两个候选实现。H2 验证失败时停在第 0/1 阶段形成实际失败证据，重新比较方案，不静默放宽事务规则。

首版携带完整、可再分发的 Java 17 运行时，记录来源、补丁版本、校验和和许可；通过完整功能验收后才考虑 jlink 裁剪。Electron 负责外层安装和分发，不再嵌套第二个 Java 安装器。

## 四、运行、数据和登录设计

### 4.1 启动与退出

1. 用户双击 OtakuLog 图标，主进程申请同一资料目录的单实例锁。
2. 第二次打开只唤起现有窗口，不启动第二个 Java 服务。
3. 主进程核对资料目录可写、运行时完整及数据库版本，再启动随包 Java，隐藏控制台窗口。
4. 服务仅绑定 127.0.0.1，使用系统分配的空闲端口，不抢占现有 8080。
5. 健康信息包含端口、程序版本和数据库就绪状态；主进程验证它属于自己启动的子进程后建立会话。
6. 独立窗口加载本地页面。启动超时 60 秒时显示中文错误、日志入口与重新启动按钮，不无限白屏。
7. 首版关闭窗口即退出。存在未保存感想、导入、恢复或正在调用 AI 时先按业务状态提示，避免直接杀进程。
8. 正常退出先停止接收新写入，等待正在执行的事务完成，再关闭数据库和 Java；超过 15 秒说明仍在退出，强制结束须由用户明确选择。
9. 桌面主进程异常退出时通过控制通道断开通知后端结束；下次启动检查本资料库实例的归属，不按 java.exe 名字批量终止进程。

### 4.2 数据目录

建议默认固定为 `%LOCALAPPDATA%\OtakuLog\`，由主进程传递绝对路径，不能依赖当前工作目录。

```text
OtakuLog\
  data\            H2 数据库、迁移版本和资料库标识
  config\          非秘密设置、窗口位置和主题
  secrets\         经 Windows 保护的密文
  backups\         版本升级前备份、每日自动备份
  logs\            脱敏运行日志
  cache\           可重新获取的封面等缓存
  web-profile\     Electron 页面运行资料，不存业务记录和 API 明文
```

- 免安装版和安装版使用相同的稳定 appId 与默认数据目录；切换分发形式可以继续使用同一资料，但不能同时打开写入。
- 首版“免安装”指无需安装即可运行，数据仍在用户目录；不是把 exe 复制到 U 盘就自动带走全部数据。跨电脑用完整备份迁移。
- 单文件 exe 运行时可以解压程序组件到临时目录；数据库和密钥不能写进这个临时目录。
- 设置提供“打开数据目录”“导出备份”“查看版本”，普通用户不需要知道 JDBC 地址。
- Windows 账号本身提供用户目录隔离；本地免登录不等于数据库全盘加密，也不提供同一 Windows 账号内的多人物理隔离承诺。

### 4.3 免登录与内部身份

保留网站模式的现有表单登录。仅桌面配置启用无交互引导，避免把服务器模式也改成匿名可写。

- 主进程生成每次运行独立的高强度随机控制凭据，通过子进程标准输入初始化后端，不写入 URL、进程参数、日志、配置或备份。
- 桌面内部控制接口必须同时满足回环访问与控制凭据校验，只有它可以建立本地会话、更新内存中的 AI 密钥和请求后端退出。
- 主进程完成一次性会话引导后把 HttpOnly 会话 Cookie 放入专用 Electron session；网页继续使用原有 CSRF 机制。
- 后端给已通过引导的会话稳定本地身份 `desktop-local`。当前导入与推荐使用的 Principal 仍然存在，不通过全面 permitAll 省略归属校验。
- 普通页面身份不能访问内部控制接口。无凭据浏览器请求、跨站表单、错误 Host/Origin 的写入均应拒绝。
- 导入旧备份时保留原历史批次的 owner 和审计原文，不为适配新身份静默重写；旧请求编号不能当成新会话可重发的请求。新操作使用新请求编号。

## 五、数据库与旧资料迁移

当前正式数据库是 MySQL；现有 H2 测试使用内存模式及 create-drop，不验证文件持久化或正式 Flyway。桌面版不能沿用该测试配置。

- 新增独立的桌面 Flyway 目录 `src/main/resources/db/desktop/`，只在 desktop 配置启用；不扫描 `classpath:com/otakulog` 下 MySQL 专用 Java 迁移。
- `V1__desktop_schema.sql` 建立与当前 V15 功能等价的桌面空库，保留唯一键、外键、固定锁行、配额行、微秒时间精度和必要索引。
- 桌面配置保持 `spring.jpa.hibernate.ddl-auto=validate`，禁止 create、update 或失败后自动删库重建；桌面空库不启用非空数据库自动基线。
- 原 MySQL V0—V15、V6.1 与 V8 历史迁移不改校验和。以后涉及两种数据库的结构变更分别提供迁移并分别验证。
- 验证 ENUM 映射、布尔、日期边界、文本长度、排序/大小写差异、唯一约束及悲观锁；不靠 H2 MySQL 兼容模式宣称全部兼容。
- 当前自用 MySQL 保持原样。迁移入口是用户导出的完整 JSON：桌面空库预览、确认恢复、重新导出并比较；不让桌面程序自动扫描或连接本机 MySQL。
- 对照时允许导出时间与文件内引用 key 重编号变化；按稳定业务标识规范化关联后比较所有业务字段、UUID、原文、来源、版本、微秒审计和调用历史，不能只比作品数量。
- 恢复继续按 quota → import_lock → 作品顺序加锁；UUID 同号差异冲突，未知观看日期保持 NULL，恢复不外发 HTTP、不降低当天预算。
- 全部写入与恢复验收使用本次生成的临时资料目录、虚构资料和归属标识；现有 MySQL 的写入验收继续只用 scripts/demo.cjs 的随机隔离库。

## 六、AI、离线和备份体验

### 6.1 自备 API Key

- 设置入口：设置 → AI 服务。首版固定 DeepSeek 服务地址与已支持模型，不开放任意代理地址。
- 展示 AI 开关、密钥输入/替换/清除、是否已配置、每日调用次数上限和说明链接。页面读取只返回配置状态及脱敏提示，不回传完整密钥。
- 固定说明：“AI 辅助整理为可选功能，需配置你自己的 API Key。调用可能产生费用，由模型服务商收取；只有你明确发送的文字会交给该服务处理。”
- 密钥在 Electron 主进程通过 Windows 系统能力加密后保存；[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)在 Windows 使用 DPAPI，不能保证抵御同一登录用户下的恶意程序。换电脑或无法解密时要求重新输入，不回退明文保存。
- 桌面主进程通过受保护控制通道更新 Java 内存配置；无需为换密钥自动重启数据库。删除时清除本地密文与后端内存值，不删除历史观点。
- 更换密钥不重置已消耗的应用预算，不自动重试旧请求。调用进行中时禁止更改配置并说明原因，待结束后允许保存。
- 不在初始化或“保存设置”时调用供应商。若提供测试连接按钮，明确说明会发起真实请求及可能计费，使用固定虚构短句，不发送个人感想。
- 密钥不写进前端 localStorage、日志、截图、异常正文、备份和发布产物；出厂状态关闭 AI，打包进程不继承开发者的密钥与个人配置。

### 6.2 离线可用

- 将 Chart.js、Sortable、marked、DOMPurify 从现有锁定开发依赖复制到静态 vendor 目录，随包携带许可与版本清单，取消页面运行时 CDN 脚本。
- 断网仍可新增、编辑和删除记录、记进度、写感想、手工整理观点、看已有统计、导出恢复。
- Bangumi 搜索、导入、推荐、以图搜番、在线 AI、WebDAV 明确显示联网需求；错误不影响已保存本地内容。
- 远程封面可缺失，显示本地占位；已有缓存可以展示，不承诺完整封面离线镜像。
- 桌面模式关闭现有 Service Worker 注册，防止随机端口与静态缓存造成旧页面；网站模式另按原逻辑维护。
- 主题、语言、窗口位置不能只依赖随机端口下的 localStorage，改由桌面非秘密设置持久保存。

### 6.3 备份、升级和回退

- 手动完整导出继续复用 BackupService 当前 v6；旧 v1—v5 和旧数组恢复规则继续保留，不因为桌面化而另造精简备份格式。
- 每个有修改的自然日首次稳定保存后生成一次自动完整备份，保留最近 7 个每日成功备份；升级前备份单独保留，不混入每日轮转。
- 一致性：生成 JSON 快照时加上能覆盖备份的所有写入入口的读写屏障；一份快照内不允许穿插写事务。跨数据库不只靠默认事务隔离级别保证一致。
- 写备份先写临时文件、校验后原子替换；空间不足只提示并保留原备份，不删除旧资料凑空间。
- 数据库结构或 H2 引擎升级前，先验证旧版本导出成功，再停库保留旧引擎可恢复的快照；不复制正在使用的数据库文件。H2 [官方备份说明](https://www.h2database.com/html/tutorial.html#upgrade_backup_restore)区分在线 SQL 备份与停库文件备份。
- 迁移失败保留原目录和备份，不反复尝试半完成升级；旧软件发现较新数据格式应拒绝写入并提示使用匹配版本。
- 首版更新采用用户在 GitHub 下载新程序并替换/安装，程序启动时按版本执行升级；不实现后台下载后静默替换。
- 卸载默认保留个人资料；彻底清空放在设置中单独确认，不在卸载默认流程执行。

## 十、阶段风险、完成定义与接续

| 风险 | 处理门槛 |
|---|---|
| 数据库迁移表面成功但业务语义变化 | 第 1 阶段必须有真实文件库、并发与跨库完整备份对照；失败不进入发布 |
| 包体或资源偏大 | 第 0 阶段记录整包与全部进程数据，测量后决定是否裁剪运行时或重新选壳 |
| 断网打不开页面 | 第 4 阶段全新资料目录、实际断网验证，不能只靠已有缓存 |
| 免登录变成匿名可写 | 第 2 阶段验证本地身份、控制通道、CSRF 与网站配置隔离 |
| 升级丢数据、自动备份不可恢复 | 第 5 阶段实际演练失败和恢复；未验收不向自用资料库迁移 |
| 免安装程序被防护软件阻止 | 对受测成品调查并记录；不绕过防护，不提前承诺任何机器无提示 |

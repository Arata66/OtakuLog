# 跨作品感想回顾实施计划

> 使用 executing-plans 在当前会话顺序实施；复用现有开发工作区，不分派新代理。用户已授权开始；一次集中检查，新增真实失败才追加定向验证。

**目标：** 跨作品筛选和阅读感想，并精确返回原记录继续操作。

**架构：** Spring Data 动态只读查询与独立前端控制器；原详情增加可选定位参数，复用原保存与冲突逻辑。

**技术栈：** Java 17、Spring Data JPA、Thymeleaf、原生 JS/CSS、现有 Node 与 Electron 验证工具。

## 文件职责

| 文件 | 职责 |
|---|---|
| `MemoryReviewController.java`、`MemoryReviewService.java` | 只读条件校验、分页和定位 |
| `MemoryReviewDTO.java`、现有两个 Repository | 轻量返回、动态条件与同作品位置查询 |
| `memory-review.js`、`memory-review.css` | 筛选、只读呈现、加载状态与返回原记录 |
| `anime-app.js`，复用 `anime-memory.js` | 打开指定记忆分页及关闭详情后刷新 |
| 模板、桌面导航、事件白名单、Service Worker | 可见入口、固定动作及资源版本 |
| `MemoryReviewTest.java`、Node 与桌面回顾场景 | 数据口径、前端并发和实际闭环 |

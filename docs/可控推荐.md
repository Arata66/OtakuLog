# 可控推荐

登录后打开图表页的推荐区，选择“推荐条件”。年份按作品首次播出时间，起止年份都包含端点，留空不限制。永久排除标签按完整实际标签核对：例如“机战”不会扩大成所有科幻。条件会保存，候选少或为空时不会自动放宽。

可以明确选最多3个喜欢的标签；留空时使用个人评分至少7分且未放弃作品的前三个高频标签。未评分收藏不当作喜欢依据，无依据时提示选标签。当前没有把感想确认观点自动映射成Bangumi题材。

默认避开已在库、外部已看／在看／搁置／放弃和“不感兴趣”作品。“包括已在库／已看”可用于重看，显示相应标记；外部在看／搁置／放弃及“不感兴趣”仍避开。每张卡片的“不感兴趣”“已看过”只影响推荐，不新增作品、观看进度或日期；在“推荐反馈”列表可撤销。撤销后仍保留防重历史，响应丢失的原请求重试不会重新启用。

候选实际出现在推荐区视口后才记录7天近期去重，读取接口本身不记展示。可明确勾选“查看近期推荐”，永久条件仍有效。切换条件或换一批时旧响应不能覆盖新结果；反馈尚未返回时保存条件，会立即撤下旧候选并在反馈确认后刷新。

## 来源、空状态与边界

每批通过Bangumi官方tag及air_date过滤召回最多60个编号，核对动画类型、完整标签和日期后排序，最多展示10个。实际共同标签数优先，再按大众分和稳定编号排序；理由仅描述真实匹配标签。未知年份在有年份限制时排除，详情缺失不作为符合条件的证据。

整轮来源或全部详情失败显示错误，可重试；部分失败显示未核对数量，硬条件没有新候选时显示空状态。采用最多4个上游线程、2批并发、45秒总核对时限，复用既有缓存；推荐批次绑定本地登录身份，15分钟到期。批次过期或条件／库内资料变化时重新读取；不自动重复发送失败反馈。

当前是单人资料库，条件和反馈属于共同实例。登录身份用于保护批次和请求归属，不构成多用户资料隔离；向别人提供共同实例前需另行设计账户与数据隔离。

## 持久化与备份

V14包含`recommendation_preference`单例条件、`recommendation_feedback`反馈及撤销历史、`recommendation_shown`近期缓存。短事务使用固定`import_lock`，上游HTTP在事务外。条件保存和撤销核对版本；反馈UUID持久防重，客户端只提交服务端已核对批次的作品编号。

完整备份v5新增`recommendationPreferences`及`recommendationFeedback`，共十二类集合。稳定编号、完整内容、版本与审计不同会冲突，禁止覆盖本地条件；不同UUID对同作品同时活动也拒绝。旧v1—v4仍兼容且不删除本地新数据。展示缓存及运行批次不备份，恢复不请求上游，详见[备份与恢复](备份与恢复.md)。

## API

全部接口需要登录；PUT、POST、DELETE需要当前页面CSRF令牌。返回遵循`ApiResponse`，错误同时使用相应HTTP状态。

| 方法与路径 | 请求或结果 |
|---|---|
| `GET /api/recommendations?includeRecent=false` | 条件、依据标签、候选、批次编号、状态及排除／核对数量；只读 |
| `GET /api/recommendations/settings` | `key`、`version`、`minYear`、`maxYear`、`excludedTags`、`recallTags`、`includeTracked` |
| `PUT /api/recommendations/settings` | 上述完整字段；初次`key=null,version=0`，之后使用返回UUID和版本 |
| `GET /api/recommendations/feedback?page=0&size=20` | 活动反馈分页，单页最多50条 |
| `POST /api/recommendations/feedback` | `requestKey`、`batchKey`、`subjectId`、`kind`，类型为`NOT_INTERESTED`或`WATCHED` |
| `DELETE /api/recommendations/feedback/{key}?expectedVersion=0` | 撤销，保留历史 |
| `POST /api/recommendations/shown` | `batchKey`、`subjectIds`，只接受该批次实际展示的最多10个独立编号 |

字段缺失、类型错误、未知字段或非法范围为400；版本、条件或资料变化为409；批次不属于当前身份或到期为404；上游失败为502。永久排除最多50个标签，规范化后重复标签拒绝。旧`GET /api/anime/recommendations`委托相同策略并保留数组返回；展示缓存必须通过新接口记录。

## 验证与使用范围

策略、来源HTTP契约、API及备份行为由Java测试核对；真实MySQL覆盖V13升级、并发反馈、重启与原数据保留，H2不能替代迁移验证。Node覆盖迟到响应、条件冲突、安全文字和响应丢失重试，浏览器回归只写随机隔离库和虚构样例，命令见[浏览器核心回归](浏览器核心回归.md)。

真实手机、Firefox／Safari、供应商网络稳定性和推荐主观质量继续单列验证。给别人使用的服务器或exe方案，在后续可核对画像推荐完成后集中说明。

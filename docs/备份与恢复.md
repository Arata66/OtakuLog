# 备份与恢复

## 页面操作

登录后使用菜单中的 JSON 导出保存备份文件。文件包括作品资料、逐集观看日期与来源、观影记忆、观点、非秘密AI调用历史、标签、分组和关联、外部收藏与导入历史、推荐条件、反馈历史与观点推荐关联，也包含历史审计时间；不包含登录密码、AI或WebDAV凭据及运行配置。

选择 JSON 导入后，页面先展示各集合数量与新增数量，包括推荐条件、含撤销记录的反馈历史及推荐关联。取消确认不会写入；存在冲突会展示原因并停止。确认后服务器重新检查当前数据库，整批成功才提交，任意写入失败都会回滚。

恢复采用合并方式，本地额外数据不会删除。对于已有作品，保留本地资料和更高进度，可补充缺失的 Bangumi ID；备份进度更高时更新进度、状态与完成日期。标签和分组关联取并集。重复恢复同一文件不会增加重复项。

已有作品的名称或 Bangumi ID 指向不同对象、本地重名无法确定身份、同名分组资料不同、同集已知日期或来源不同都会冲突。请先核对文件与本地数据，解决差异后重新预览。未知日期不会覆盖已知日期，备份中的已知日期可补齐本地未知日期。

## 文件格式

顶层对象固定为 `format: "otakulog-backup"`、`version: 6`，含 ISO 格式 `exportedAt` 和以下数组：

| 集合 | 数据与关联 |
|------|------------|
| `anime` | `key`、`data`（全部作品标量字段和审计时间）、`tagKeys` |
| `tags` | `key`、名称、创建时间，包括未使用标签 |
| `groups` | `key`、名称、说明、颜色、排序及审计时间，包括空分组 |
| `memberships` | `groupKey` 与 `animeKey` |
| `episodes` | `animeKey`、集号、可空 `watchedDate`、`source`、审计时间 |
| `memories` | 稳定UUID `key`、`animeKey`、原文、喜欢/不满意原因、评价范围、语境、可空观看日期、版本与审计时间 |
| `insights` | 稳定UUID `key`、`memoryKey`、来源版本、当前观点字段、状态、来源、模型原建议六字段、`aiCallKey`、修订版本及审计时间 |
| `aiCalls` | `requestKey`、`memoryKey`、来源版本、输入哈希、模型与提示版本、选文字数、状态、安全错误类别、可空用量及审计/完成时间 |
| `externalCollections` | 稳定UUID `key`、来源账号、Bangumi作品ID、原始字段JSON `payload`、版本、抓取与审计时间 |
| `importBatches` | `requestKey`、本地登录归属、来源账号、确认选项指纹、原结果JSON及审计时间 |
| `recommendationPreferences` | 最多一条永久条件，含稳定UUID、版本、年份、排除／召回标签、库内开关及审计时间 |
| `recommendationFeedback` | 活动及已撤销反馈，含请求UUID、归属、来源批次、作品ID／名称、类型、活动状态、版本及审计时间 |
| `recommendationBases` | 稳定UUID、观点UUID、来源及观点版本、语义指纹、正负方向、标签或种子目标、启用状态、修订版本及审计时间 |

作品、标签与分组的 `key` 仅为文件内引用。观影记忆的 `key` 为全局稳定UUID，用于识别同一条记忆；其 `animeKey` 仍为文件内作品引用。恢复会重新建立本库 ID 映射，不把源库 ID 写到目标库。日期使用 `yyyy-MM-dd`，时间使用 ISO 本地日期时间；来源只允许 `WATCHED`、`MANUAL`、`IMPORT`、`LEGACY`。`WATCHED` 必须有日期。

完整格式要求显式包含字段，可空字段使用 `null`。不接受未知版本、额外字段、错误类型、重复 JSON 属性、重复 key、重复关联、悬空引用及超出字段长度的文字。历史可空审计时间保持未知；历史完成状态与进度不一致时原样保留。数据库时间精度按现有列定义保存。

版本一至五继续兼容，不删除本地新集合。版本一不能夹带记忆、观点或调用数组，版本二不能夹带观点或调用数组；前三个版本均不能夹带外部集合，前四个版本均不能夹带推荐条件／反馈，前五个版本不能夹带推荐关联。版本三包含原有八类数组，版本四含十类，版本五含十二类，版本六必须包含全部十三类数组。记忆、观点、调用及外部记录的稳定编号、归属、全部内容、版本与审计时间一致才跳过；不同则整批冲突，不自动覆盖。不同编号的相同文字仍分别保留。新记录时间最多支持微秒精度，超过时先拒绝，避免数据库舍入导致重复恢复误报冲突。

推荐条件是单例：本地与文件中的UUID、完整字段、版本及审计时间必须一致，否则拒绝覆盖。反馈最多100000条，同UUID差异或不同UUID对同作品同时活动均冲突；撤销记录保留防重历史，重复恢复不重新启用。7天展示缓存、运行中的推荐批次不进入备份，也不参与业务内容比较。恢复不请求推荐来源，详见[可控推荐](可控推荐.md)。

推荐关联最多1000条，每个观点只能有一个关联；同UUID的来源、完整目标、状态、版本或审计不同，以及不同UUID对同观点重复关联，均拒绝恢复。来源已删除或改变的记录可以保留为暂停历史；只有原文、观点语义及版本全部匹配才可使用。语义指纹不依赖自增ID，重映射来源ID不使有效关联失效，同UUID不同原文不能误绑定。恢复不会请求Bangumi或AI。

外部收藏的编号及“来源账号＋作品ID”必须同时一致；同编号或同来源身份的原文、版本或审计不同会冲突。内层JSON同样校验完整字段、类型、重复属性与长度，不接受历史计数为null。导入批次只保留防重历史，恢复不读取上游或执行导入。每个外部集合最多100000条，单条原始JSON最多64000字节；运行中的预览缓存不进入备份。

观点通过稳定 `memoryKey` 引用文件内记忆，来源版本不能超前。当前版本引用必须仍在原文字段中；旧版本允许保留失效引用，不能因此进入当前总结。AI原建议独立于用户改写，必须有文件内对应成功调用且记忆归属一致；手工观点没有模型来源。调用历史允许保留已删除来源的记忆UUID，不把它强行绑定到新恢复的旧记忆版本。

恢复不调用AI，也不重新执行RUNNING请求。新恢复的RUNNING仅在本地标记为历史，原状态与审计时间保留；`historyOnly`不进入文件或UUID内容比较，已有本地请求不因重复恢复被改成历史。历史记录显示结果未知，同请求键始终不外发。所有格式的恢复均先锁预算行，再锁固定导入行，之后按顺序锁作品，全部集合与额度同一事务；当天已预留次数不低于原本地计数和合并后的当天调用数量。详情见[口味画像](口味画像.md)。

旧版作品数组仍可导入，标签支持逗号字符串、名称数组及标签对象数组。旧格式不包含完整观看历史与分组，缺失逐集记录仅补 `NULL` 日期与 `IMPORT` 来源，不能降低已有进度，也不会将补录日期设为导入当天。名称重复且资料相同的旧条目合并，资料不一致则拒绝。旧格式一次最多补齐 100000 条逐集记录，超过时需拆分文件。

## WebDAV

WebDAV 是通过 HTTP 读写远程文件的协议。这里用它把备份保存到自己的网盘或服务器，再手动下载恢复；它是可选功能，没有 WebDAV 服务时仍可使用 JSON 导出与导入，不需要另行开通。

配置沿用 README 的 WebDAV 设置。推送上传相同完整格式；页面拉取先下载并预览，再用 SHA-256 摘要确认。确认时重新下载，如果文件已变化则拒绝恢复并提示重新预览。实际恢复继续经过相同校验和事务。

这是手动备份与合并恢复，不传播删除，不实现双向自动同步或自动冲突决策。备份文件是明文个人数据，请保存在自己控制的位置。

推送与拉取共用忙碌状态，执行或确认期间两个按钮均禁用；完成、失败、取消或预览冲突后恢复。拉取成功会刷新作品、统计、继续观看和热力图。认证凭据固定用 UTF-8 编码，避免运行系统字符集改变凭据字节；远程服务仍需支持相应认证方式。

## API

所有接口需要登录会话；POST 需要当前页面的 CSRF 令牌。认证规则见 README。

| 方法与路径 | 请求 | 返回 |
|------------|------|------|
| `GET /api/anime/export` | 无 | 完整 JSON 文件 |
| `POST /api/anime/import/preview` | 原始 JSON 文件内容 | `data.valid`、数量、`warnings` 与 `conflicts`；不写入 |
| `POST /api/anime/import` | 同一原始 JSON 内容 | 成功数量；冲突或格式错误返回 HTTP 400 |
| `POST /api/sync/push` | 无 | 上传结果 |
| `POST /api/sync/pull/preview` | 无 | 预览结果与 `fingerprint` |
| `POST /api/sync/pull` | `{"fingerprint":"预览摘要"}` | 恢复结果；文件变化返回 HTTP 400 |

预览接口在无法恢复时返回 `data.valid=false` 和具体冲突；HTTP 200 表示预览请求完成，不代表文件可恢复。`created` 为新增作品数，`updated` 为匹配合并作品数，不代表资料被覆盖；`newEpisodes` 为新增记录数，`filledDates` 为可补齐日期数。`memories`/`insights`/`aiCalls`为文件内对应数量，`newMemories`/`newInsights`/`newAiCalls`为将新增的数量。

直接调用旧版无请求体的 WebDAV 拉取 API 仍兼容，也执行结构、身份、日期冲突校验；若需要保证确认的是同一远程文件，请始终传入预览摘要。

## 验收与故障处理

桌面 H2 文件库新增真实 MySQL→H2、H2→H2 的完整 v6 往返、重复恢复与重启验证，按稳定业务标识对照全部十三集合；旧数组与 v1—v5、同 UUID 内容冲突、损坏文件零部分写入、RUNNING 仅作历史且不外发也有文件库回归。原批次 owner 与微秒审计保留，不替换为桌面身份。测试范围、运行条件与尚未交付的自动备份见[本地数据库验收](桌面版本地数据库验收.md)。

自动化覆盖空库恢复、ID 重映射、重复恢复、未知日期、身份和日期来源冲突、分组冲突、非法结构、旧格式兼容、中途回滚及模拟 WebDAV HTTP。新增本地 HTTP 服务验证真实认证、原始 JSON、HEAD 状态、只读预览、摘要变化、401/503和空文件；另在非 UTF-8 JVM 下运行，防止 Linux 默认字符集掩盖 Windows 问题。

三个 Chromium 用例通过真实后端和随机 MySQL 验证完整推送、取消、确认恢复、重复恢复、首页与热力图刷新、远程变化、冲突、认证/服务失败和重复点击防护，逐库核对清理。当前未配置真实 WebDAV 服务，本节不证明网盘厂商、TLS 或远程目录权限已验收；后续需使用用户指定的独立目录和临时文件。自用数据库不做恢复实验。

导入失败时保留源文件，查看返回原因；修正后重新预览。不要手动修改 Flyway 历史或删除用户数据来绕过冲突。此备份覆盖应用数据，不能替代升级前的数据库级备份。

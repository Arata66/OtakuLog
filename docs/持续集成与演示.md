# 持续集成与隔离演示

## 自动检查

`.github/workflows/ci.yml` 在推送、PR 和手动运行时检查代码。使用 GitHub 托管 Ubuntu 24.04、Java 17、Node 22 和独立 MySQL 8 服务，只授予仓库读取权限；同一分支的新运行取消旧运行。Action 固定到完整提交 SHA，不跟随可变版本标签。

运行 Java 干净构建与全部测试、前端和演示工具测试、真实演示应用冒烟、JavaScript 语法和提交空白检查。测试报告、Node 输出与演示日志保留 7 天，失败也尝试上传。CI 数据库密码只是工作流临时测试服务配置，不使用个人凭据或自用数据；此工作流不部署应用，不自动合并。

MySQL 测试随机创建 `otakulog_verify_` 库。演示冒烟另外创建 `otakulog_demo_` 库，启动打包后的应用、恢复虚构样例、执行进退集、来源核对和快照冲突验收，正常退出后检查库已删除。CI 包含真实数据库验证，不能用本地 H2 结果代替远程运行结果。

Action 版本核对来源：[checkout](https://github.com/actions/checkout/releases/tag/v7.0.1)、[setup-java](https://github.com/actions/setup-java/releases/tag/v6.0.1)、[setup-node](https://github.com/actions/setup-node/releases/tag/v7.1.0)、[upload-artifact](https://github.com/actions/upload-artifact/releases/tag/v7.0.2)。

## 启动独立演示

需要 Java 17 或更高版本、Maven、Node.js 22 或更高版本、本地 MySQL 8 与 `mysql` 命令。数据库账号需具备创建、迁移和删除演示库的权限。

在项目根目录执行：

```powershell
# 按本地环境设置，密码不填在启动命令参数中
$env:JAVA_HOME='C:\Program Files\Java\jdk-17.0.18'
$env:Path="$env:JAVA_HOME\bin;$env:Path"
$env:DB_USER='root'
$env:DB_PASS='本地数据库密码'
mvn clean verify
node scripts/demo.cjs
```

默认演示地址为 `http://127.0.0.1:18080`，使用终端打印的 `demo` 账号和**本次随机密码**；登录页通用默认账号提示不适用于演示。需要其他端口时使用 `node scripts/demo.cjs --port=18081`，8080 被保留给日常预览。

脚本每次创建新的随机库，显式指定该数据源，保持 JPA `validate` 与 Flyway 迁移，然后通过独立 Cookie、表单登录、CSRF 和备份恢复接口导入样例。只接受 `OTAKULOG_MYSQL_SERVER=127.0.0.1:3306` 或 `localhost:3306` 形式的本地地址；端口可调整。数据库密码通过子进程环境传递，不进入命令行，临时演示登录凭据不写入项目文件。

虚构备份在 `src/test/resources/fixtures/demo-backup.json`，包含 4 部作品、1 个标签、1 个分组、3 条分组关系和 7 条逐集记录：明确日期、未知日期及 LEGACY 都可测试。星港巡游距完成一集；雨巷来信用于来源核对；海边放映室已完成；下一站山城为计划作品。固定样例日期用于重复验收，不随启动时间改写，没有真实用户资料、Bangumi ID 或外部封面。

## 停止、失败与清理

工具在当前终端前台运行，按 Ctrl+C 停止；先关闭自己持有的 Java 子进程，再删除本次成功创建的库。建库失败不会删除可能已有的库，端口占用时不建库；启动或样例恢复失败会清理本次库。若子进程无法停止，报告错误并保留库供核对。日志保留在 `.demo/otakulog_demo_*.log`，已由项目的日志忽略规则排除。

强制结束终端进程、断电或系统重启可能来不及运行清理，工具不承诺这种情况下自动删库。本次跨日会话中断确实产生过一个残留；核对虚构作品和无活动连接后已清理。若遇到残留，从本次终端输出或日志确认完整库名，检查相关演示进程已停止、没有连接且确为虚构样例，再手动删除**这一个**库。不要批量按前缀清理，也不要删除 `otaku_log` 或 `otakulog`。

## 本地完整回归

```powershell
$env:OTAKULOG_MYSQL_TEST='true'
mvn clean verify
$env:OTAKULOG_DEMO_TEST='true'

```

未启用这两个变量时，MySQL Java 测试与真实演示 Node 冒烟默认跳过，其余测试仍运行。演示工具本身使用 Node 内置模块，无需 npm 安装依赖。

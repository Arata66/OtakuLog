# 日常追番入口与进度反馈

登录后，首页上方显示“继续观看”和“今日放送参考”。手机为单栏；点击作品名称查看详情，点击“记看第 N 集”使用原有下一集接口保存实际观看进度。

## 列表规则

继续观看仅包含追中、总集数已知、当前进度非负且尚未到总集数的作品；首页最多显示 6 部，总数不截断。按最近明确观看日期降序排列，日期未知的排在后面，再按自定义排序、名称和 ID 稳定排列。该入口不受下方搜索、筛选或分页影响。

最近观看日期取逐集记录中不晚于服务器当天、来源为 WATCHED、MANUAL 或 IMPORT 的最大日期。只有 LEGACY、未知日期或未来日期时显示“最近观看日期未知”，不用作品资料更新时间推测观看。主动补录日期后入口重新读取。

今日放送参考从全部可继续作品中核对当前 Bangumi 日历，也最多显示 6 部，总数不截断。有 Bangumi ID 时只按 ID 匹配；无 ID 时接受去首尾空格、忽略大小写后的完整日文或中文名称，且必须唯一。同名歧义不猜，已有 ID 不以名称覆盖。使用日历星期，排除本地或日历开播日期明确在未来的作品，不沿用本地历史星期，也不根据集数或个人看完日期猜放送结束时间。

日历未收录的旧番仍可在继续观看中补番；未收录本身不证明已完结。日期和星期使用服务器本地日期；当前预览为 Asia/Shanghai。日历复用 30 分钟缓存，不写回作品或观看记录；核对也不证明本周一定更新、剧集已上线。

## 进退集与失败处理

同一作品保存期间，日常入口、表格、卡片和详情中的进退集按钮同时禁用；新渲染的按钮也遵守这一状态。不同作品可独立保存。返回成功后使用服务端进度，显示具体集数，以及自动完成或退至计划的结果，并刷新列表、统计、热力图、日常入口和当前详情。

详情无日期草稿时刷新逐集记录；有草稿时保留输入并提示重新加载核对。退集使历史页超出范围时重新读取最后一页。详情不会整体重建，避免丢失日期输入。

边界错误显示“已经是最后一集了”或“已经是第 0 集了”。网络中断可能发生在服务器提交之后，页面提示刷新核对，不在本地假推进，也不自动重试。按钮防重复只覆盖当前页面中的待响应操作，不提供跨窗口幂等保证。

日常列表刷新失败时保留已有内容并标注可能过期，停用其中的记进度按钮，重新加载成功后恢复；其他区域的进退集操作仍使用服务端校验。首次加载失败提供重试，空列表给出添加或开始追番的指引。

继续观看先从本地数据加载，随后独立核对放送日历，不拖住记进度及其刷新。核对中显示“核对中”；外部失败、空日历或必要字段无效时显示“未核实”，不显示 0 部，也不回退历史星期。只有成功核对后才显示实际数量，包括确实没有匹配时的 0 部。重新加载、进度刷新产生的新请求使旧响应失效；日期不同的响应不接受，服务端核对跨午夜也返回未核实。

## 接口与结构

`GET /api/watch/daily` 与 `GET /api/watch/airing` 均需要登录；匿名访问返回 HTTP 401。无需 CSRF 令牌，不生成观看记录或变更作品。前者只读本地一致性快照，默认不查询日历；后者先获取完整本地快照，事务结束后再请求外部日历。没有可继续作品时可直接确认今日参考为 0，无需外部请求。

响应沿用 `ApiResponse`，以下字段位于 `data`：

| 字段 | 含义 |
|------|------|
| `date` / `weekday` | 服务器 ISO 日期与星期，周一为 1、周日为 7 |
| `ongoingCount` / `todayAiringCount` | 可继续作品与今日参考的完整总数；未核实时后者为 null |
| `continueWatching` / `todayAiring` | 各最多 6 条，使用相同排序规则 |
| `airingStatus` | 本地入口为 `UNVERIFIED`；独立核对成功为 `VERIFIED`，失败或数据无效为 `UNAVAILABLE`；未核实时今日列表为空 |
| 列表项 `anime` | 完整 AnimeVO，与原列表共用映射，支持筛选之外打开详情 |
| 列表项 `lastWatchedDate` | 最近明确逐集日期，未知为 null |

`DailyWatchService` 读取追中作品，一次聚合这些作品的最近明确日期，映射与排序后输出。`DailyAiringService` 在读取事务外调用 `BangumiService.getCalendar()`，不复用会写回资料的放送日历服务。前端由 `daily-watch.js` 展示，并以请求序号和日期保护独立核对结果，只更新放送区域数据；`watch-actions.js` 统一进退集交互，`episode-history.js` 同步详情与草稿保护。当前静态缓存为 v16；数据库仍为 V9，无新增表或迁移。

## 验证与运行

Java 用例覆盖状态与日期筛选、排序、数量截断、只读和权限，以及日历 ID/名称匹配、旧番排除、长篇保留、未来开播、上游失败/无效数据和事务/跨日边界；真实 MySQL 隔离库验证 IMPORT 日期聚合、LEGACY 排除、记完移出入口与退集恢复。Node 用例覆盖独立加载、核对失败不误报数量、迟到/跨日响应、请求去重、具体反馈、网络结果不明、输入转义和详情联动。浏览器通过虚构日历结果验证桌面/手机参考列表与故障提示，并在日历等待期间真实记看；上游匹配逻辑由 Java 测试覆盖。

启动方式见README。登录后可只读请求`/api/watch/daily`，检查日期、列表数量、来源提示和新脚本加载；不要在真实自用库点击记看或核对按钮做写入验收。2026-10-09在独立虚构样例中验证最后一集完成、退集恢复、详情联动和未知日期补录后的首页刷新；[浏览器核心回归](浏览器核心回归.md)另覆盖原生弹窗取消与两个独立登录窗口的409冲突，2026-10-10扩展360像素手机深色下的逐集核心流程；其他浏览器与外部服务仍未全面验收。演示启动见[持续集成与演示](持续集成与演示.md)。

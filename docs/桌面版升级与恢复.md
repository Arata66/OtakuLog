# 桌面版升级与恢复

桌面版默认资料位于 `%LOCALAPPDATA%\OtakuLog`。更新程序不会搬走资料；免安装版和安装版共用同一资料目录。正式安装、卸载与干净 Windows 的验证仍在发布前清单中。

## 升级前会做什么

当前自动升级范围是同一个锁定 H2 引擎版本内的数据库结构迁移。程序先核对引擎标记和独占资料锁，检查 Flyway 历史；只有存在待执行的结构迁移时，才创建独立升级备份。

升级备份位于 `backups\upgrade` 下的唯一子目录，包含升级前 SQL 导出、停库文件快照及校验信息。SQL 会先在独立临时库执行恢复验证，成功后关闭原库，再保存原数据库文件快照；全部准备成功后才开始迁移。这些文件不参加每日七份备份的轮转，也不会自动覆盖同名旧备份。

程序在迁移开始前保存升级尝试状态，完成启动后才确认成功。若迁移失败、迁移期间程序被中断，或迁移后未能正常完成启动，下次打开会停止自动重试。H2 的部分 DDL 不能通过普通事务自动撤回，所以保留现场与升级前副本比再次尝试或自动覆盖更可靠。

迁移连接使用专用非池数据源，业务连接池在迁移后才使用。升级尝试记录位于 `data\desktop-upgrade.json`；它在应用就绪握手之前确认成功。普通启动有一分钟时限，识别到结构升级后给予一次最多十分钟的备份和迁移时间，重复进度消息不会无限延长等待。SQL 导出与恢复命令见 [H2 官方命令说明](https://www.h2database.com/html/commands.html#script)。

这里的 SQL 和数据库快照用于版本故障恢复，与页面“完整 JSON 备份”不同，不能把 SQL 文件选进 JSON 导入界面。日常迁移到另一台电脑，仍优先使用完整 JSON 的预览、确认恢复流程。

## 启动被拒绝时

错误提示会显示本次资料目录和备份目录；日志位于资料根目录的 `logs`。

| 提示原因 | 处理方式 |
|---|---|
| 资料被其他程序使用 | 关闭正在使用同一资料的 OtakuLog，再重新打开；不要删除锁文件来强行打开 |
| 资料结构比当前程序更新 | 使用匹配的新版本；不要删 Flyway 历史、降级结构或开启自动建表 |
| H2 引擎版本不一致 | 用匹配的旧程序导出完整 JSON，再向新程序的独立资料目录恢复 |
| 升级前备份失败 | 检查备份目录权限和磁盘空间，保留已有文件；备份未完成时不会开始迁移 |
| 上次升级未完成 | 保留整个失败资料目录与升级备份，在独立目录恢复；不要直接删除升级状态后重试 |

当前尚未实现自动跨 H2 引擎转换。首次接管尚无引擎标记的开发期资料时，只按本项目既有的 H2 2.2.224 基线处理，不代表支持打开任意来源、任意引擎版本的数据库。`data\desktop-engine.json` 是兼容性记录，不应手工修改来绕过拒绝。

## 在独立目录恢复

1. 退出使用该资料的程序，完整保留失败目录。先复制升级备份到另一处，核对其中校验信息，确认对应的原引擎和迁移版本。
2. 使用与快照匹配的程序版本，在一个全新的资料根目录内建立 `data` 子目录，将升级前数据库快照作为 `data\otakulog.mv.db` 放入。不要把失败升级目录里的尝试状态一并复制过去。
3. 通过已有资料目录参数启动匹配版本，例如 `OtakuLog.exe --data-dir="D:\OtakuLog恢复资料"`。不要把 `--data-dir` 指向原失败目录，也不要先创建新库再覆盖。
4. 核对作品、感想和观看记录后，导出完整 JSON。向另一个独立目录恢复时，继续使用原有的预览、冲突核对和确认流程；保留旧副本直到确认记录完整。

只有明确匹配版本的快照才用于文件恢复。程序没有提供自动覆盖原目录或自动执行任意 SQL 的按钮。

## 验证边界

`DesktopUpgradeTest` 使用虚构临时文件库构造 V1→V2 迁移，验证成功升级、SQL 与停库副本独立恢复、部分 DDL 失败后的阻断、未来结构拒绝、引擎不匹配及备份失败保护。桌面行为测试验证固定故障码、位置提示、后端清理等待和有上限的升级等待；真实 Electron 场景验证引擎不匹配时原文件不变、错误位置可见及恢复正确标记后原记录保留。

这些验证不等同于跨 H2 引擎转换、真实磁盘耗尽、断电耐久性或安装卸载实机验收；发布前清单仍需保留这些边界。

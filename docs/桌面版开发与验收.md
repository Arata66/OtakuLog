# Windows 桌面版开发与验收

第3阶段的桌面操作与开发环境故障场景已收齐，包含生命周期与写入期间的退出保护、原生备份导出，以及窗口和外观偏好的稳定保存，尚未发布可供日常使用的版本。界面由 Electron 独立打开，携带 Java 17，使用独立 H2 文件库；业务并发和跨库备份证据见[本地数据库验收](桌面版本地数据库验收.md)。断网业务、个人 AI 设置、自动备份与升级继续按[实施计划](superpowers/plans/2026-10-15-Windows桌面版.md)推进，干净系统人工验收统一留在公开候选阶段。

## 开发和构建

开发需要 Windows x64、Java 17、Maven 和 Node 22.12 以上。最终运行程序使用包内 Java 与 Electron，不调用系统 Java、Node 或 MySQL。

```powershell
npm ci
node scripts/vendor-assets.cjs --check
npm --prefix desktop ci
npm run desktop:lint
npm run desktop:typecheck
npm run desktop:test
mvn -Pdesktop clean verify
```

网站默认构建仍输出 `target/otakulog-1.0.0.jar`；`desktop` Maven profile 输出 `target/otakulog-1.1.0-beta.1.jar`，并将 H2 放入运行依赖。两种模式都保持 JPA `validate`。桌面使用独立的 `db/desktop` Flyway 基线，不执行 MySQL 历史迁移，不自动选择或迁移现有自用库。

桌面 Flyway 显式取消忽略未来迁移：资料结构比当前程序更新时拒绝启动，不自动删除、降级或修补迁移历史。收藏导入在桌面配置使用 `ISOLATION_READ_COMMITTED`，确保等待固定锁后可看到新提交的防重结果；网站默认仍为 `ISOLATION_SERIALIZABLE`，整批事务和既有锁顺序保留。不要通过关闭校验或修改迁移历史绕过启动错误。

桌面 `LocalDate` 直接使用 JDBC 4.2 写入和读取 H2 DATE，避免旧 `java.sql.Date` 的历史历法/时区转换偏移。此适配只在 desktop 生效，不改变全局时区、网站/MySQL 映射或时间戳类型。

运行时来源、精确版本、SHA256 和下载地址在 `desktop/runtime-windows-x64.json`。从该地址下载并核对 SHA256 后，将完整运行时解压到项目外，再执行：

```powershell
node desktop/scripts/stage-backend.cjs --jar target/otakulog-1.1.0-beta.1.jar --runtime 'C:\绝对路径\jdk-17.0.20.1+1-jre'
npm --prefix desktop run dev
```

准备脚本只复制明确指定的 JAR、运行时及其许可，写入版本、提交编号和 JAR 哈希，不扫描个人配置目录。目标 `desktop/staging` 必须为空，已有内容会拒绝覆盖；更新时先核对这是本轮生成的构建目录，再清理。开发区有未提交修改时，提交编号只表示基线，不能把该产物当成可复现发布包。

```powershell
npm --prefix desktop run test:e2e
npm run desktop:package
$env:OTAKULOG_DESKTOP_EXECUTABLE = Join-Path $pwd 'desktop/release/win-unpacked/OtakuLog.exe'
npm --prefix desktop run test:e2e
Remove-Item Env:OTAKULOG_DESKTOP_EXECUTABLE
```

打包生成免安装 exe、当前用户安装版和完整 zip，输出位于 `desktop/release`。当前没有项目代码签名；打包日志中的签名工具步骤不能作为已签名证据。此阶段产物只用于内部验收，不自动建立 GitHub Release。

四个前端依赖使用根目录锁定的 npm 包生成，脚本、许可及逐文件版本和 SHA256 清单在 `src/main/resources/static/js/vendor/`。升级依赖时先审查锁文件，再运行 `node scripts/vendor-assets.cjs` 重新生成并提交；`--check` 仅核对，不修复缺失或篡改。该目录关闭 Git 换行转换，保证 Windows 检出后仍保留上游原文。网站与桌面都从应用自身加载这些脚本，运行时不依赖 npm 或脚本 CDN。

Sortable 许可原生 CRLF、DOMPurify MPL 许可原有行末空格均逐字保留；Git 空白规则只对这两个明确文件兼容，不放宽项目源码检查。

## 数据和访问边界

- 默认资料目录为 `%LOCALAPPDATA%\OtakuLog\`；`data` 存业务库，`web-profile` 存页面会话，`logs` 存运行日志。程序目录和免安装 exe 的临时解压目录不存业务数据。
- 免安装版与安装版使用相同 appId 和默认资料目录。复制 exe 不会自动带走资料，跨电脑迁移仍需完整备份。
- 开发验收可使用 `--data-dir=绝对路径` 指定独立资料根目录；空值、相对路径和分号会拒绝。不要把自用目录作为测试目录。
- 桌面 Java 只绑定 `127.0.0.1` 的随机端口。主进程通过标准输入传递本次控制凭据，核对版本与就绪端口后建立一次性本地会话；控制凭据不在 URL、启动参数或备份中。
- 控制请求只向握手确认的固定回环地址发送，使用 Node HTTP 保留五秒总时限、不跟随重定向和非成功响应拒绝。随机端口可能被通用 fetch 的端口规则拒绝，因此不把该规则用于已确认的本机控制通道；未给页面开放任意 HTTP 能力。
- 业务接口继续要求会话和 CSRF。仅同时启用 desktop profile 与 `app.desktop.managed=true` 时免登录、隐藏退出登录入口；会话失效提示重启程序。其他配置仍使用原有网站登录。
- 收藏预览和推荐批次仍绑定当前身份；恢复保留原 owner，历史请求键不能换成桌面身份重新执行，不全局改写历史归属。
- 网页不能使用 Node，窗口开启 sandbox 与 contextIsolation，权限检查和权限申请均拒绝；弹出的 HTTPS 链接交给系统浏览器，窗口本身拒绝外部导航和外部重定向。
- 受管桌面响应的 CSP 仅允许同源脚本，禁止行内事件、动态求值、嵌入页面和工作线程；仅样式保留现有行内兼容。备注清理后仍不能执行应用命令。网站登录链不加这套桌面策略。
- 桌面不注册 Service Worker，每次启动仅清理专用会话的工作线程与 CacheStorage，不清 Cookie、localStorage 或业务库；网站保留静态资源缓存。桌面使用系统字体，网站继续加载可选的 Google Fonts。
- 退出先检查草稿和同源写入；列表导入、恢复、AI等请求也纳入保护，多个请求分别计数，响应正文读完或失败才释放。选择继续编辑会保留页面和后端；确认关闭窗口后才停止服务。壳等待十五秒后可继续等待或明确强退；后端的请求排空仍有二十四小时兜底上限。
- 后端异常和页面崩溃显示一次错误提示；重新启动在旧后端停止后才安排，草稿确认中取消退出也会取消这次重启。启动握手失败先结束本次子进程、等其关闭后报告失败，避免立即重开同一资料库。
- 桌面文件库使用 `WRITE_DELAY=0`，使已提交的记录及时落盘。故障验收曾复现“保存成功后立即结束主进程，重开丢失最近记录”，因此关闭 H2 默认的提交落盘延迟；规则见 [H2 官方说明](https://h2database.github.io/html/commands.html#set_write_delay)。这不等同于硬件断电或磁盘故障验收。
- 桌面默认关闭 AI，不继承开发者 API Key。当前尚无用户可用的密钥设置页。

## 原生备份导出

桌面点击 JSON 导出后，由主进程打开保存对话框。只有完整文件保存成功才提示“备份已保存”；取消不显示成功或失败，写入失败保留已有目标文件。导出期间按钮禁用并阻止窗口关闭，结束后恢复操作。若期间发生故障且用户已确认退出或重启，会等本次导出结束再继续退出流程。

preload 只向主框架暴露无参数的 `exportBackup()`。主进程核对当前窗口、主框架与握手确认的后端 origin，等待保存选择、会话读取和备份响应后再次核对；启动页、子框架和其他来源不得读取备份。业务读取只携带专用会话 Cookie，固定访问 `/api/anime/export`，不使用控制凭据、不跟随重定向，保留三十秒总时限与随机端口兼容。

保存复用 `BackupService` 的完整 JSON 原始字节，不另造桌面格式。文件先在目标目录完整写入并同步，再替换目标；失败只清理本次临时文件。备份恢复继续使用 HTML 文件选择、预览和明确确认，保留损坏文件拒绝及同文件重复恢复规则。网站继续由浏览器下载，提示“已发起备份下载，请在浏览器中确认保存”。

## 窗口、偏好与菜单

桌面将主题、主题色、语言和窗口正常位置、大小、最大化状态存入资料目录的 `config/settings.json`，重启或随机端口改变后仍然有效。页面在初始化外观和语言前等待读取完成，桌面忽略旧端口内的这三项 localStorage；网站继续使用原有 localStorage。主题与语言仍通过页面顶部按钮切换。

偏好 IPC 只允许三种白名单字段与合法选项，沿用当前窗口、主框架及精确后端来源校验；页面不能提供路径、窗口边界或秘密。窗口由主进程读取正常态边界，恢复时按当前显示器工作区回位。Windows 分数缩放可能让读取的边界与传入尺寸略有差异，未调整窗口保留原始保存尺寸，避免每次重开继续放大。

窗口和页面偏好使用同一个队列合并并原子写入，正常退出等待队列完成。页面设置保存期间纳入退出提醒；写入失败明确提示本次选择只在当前窗口生效。文件损坏或版本不兼容时使用默认值并保留原文件，暂不覆盖它。需要重置时，从“文件 → 打开资料目录”找到该文件，退出程序后另存并移走 `config/settings.json`，再次打开会使用默认偏好；业务数据库不参与此操作。

“文件”菜单提供资料、数据、日志三个固定目录入口与退出；“编辑”提供撤销、重做、剪切、复制、粘贴和全选；“视图”提供缩放及实际大小；“帮助”显示版本。菜单目录由主进程确定，页面没有任意路径打开能力。组合输入期间 Enter、Escape 不执行应用的搜索或弹窗关闭快捷操作。

设置文件仅保存非秘密偏好，不包含 AI 或 WebDAV 凭据，也不纳入业务完整 JSON 备份。个人密钥设置仍属于后续阶段。

## 验收方法

`desktop/e2e/startup.test.cjs` 创建随机临时 H2 资料，用虚构作品执行免登录、新增、关闭和重开，并验证列表写入等待时取消退出、继续真实保存，以及感想草稿保护。清理只针对本次创建的目录。启动环境仅保留基本 Windows 变量，PATH 只有 System32，用于检查不依赖系统开发运行时。

`desktop/e2e/lifecycle.test.cjs` 分别在 Java 完成启动前和业务保存后终止本次 Electron 主进程，核对本次 Java 退出、原文件库重开与已保存记录保留。Windows 下 Playwright 的进程对象可能是 cmd 包装进程，因此故障作用于从当前应用读取的实际主进程 PID；不按进程名结束其他应用。

`desktop/e2e/launch-failures.test.cjs` 在 8080 已占用时打开随机端口服务，并分别在首次尚未就绪和正常运行时启动第二个真实进程，核对第二个退出、原窗口恢复、唯一后端及关闭不影响其他服务。测试只在自己成功绑定 8080 时关闭该监听；端口已被其他服务使用时保留它。

同一脚本还会在就绪前和保存虚构作品后分别终止本次 Java，核对错误提示仅一次、导出拒绝、真实新增请求失败且不提示成功、重新打开仍保留已提交记录。只替代错误对话框的用户选择，不替代故障进程或业务网络。等待退出超时后的“继续等待／强制退出”由主进程行为测试验证：未明确选择前不终止，强退只作用于本次持有的子进程；真实卡住写入的人工强退仍留在发布前实机清单。

`desktop/e2e/backup.test.cjs` 使用随机 H2 资料与虚构中文记录，覆盖保存、取消、目标写入失败、完整文件恢复、同文件再次恢复、损坏预览零恢复写入，以及导出期间页面崩溃后的确认退出。测试只替代保存对话框的用户选择，HTTP、Cookie、文件落盘与恢复均真实执行；不把这项自动化当作系统对话框人工操作或干净 Windows 实机证据。

`desktop/e2e/settings.test.cjs` 使用随机资料，重开前占用本次旧端口，核对新端口下的外观、语言和最大化，以及连续重开的窗口尺寸稳定；另覆盖损坏与不可替换文件的提示和原内容保留。目录入口仅替代系统打开动作并核对固定路径。程序缩放 100%／125%／150% 与组合键事件自动化分别核对可操作性；它们不替代改变 Windows 显示缩放、真实输入法候选选择或键盘全流程的人工验收。

`desktop/e2e/security.test.cjs` 阻断渲染器外部资源，核对四个脚本实际来自当前 JAR，并执行新增、进度、感想、Markdown 与图表。注入探针由同源脚本标签原生执行，核对 CSP 拒绝行内脚本、事件属性、外部脚本及动态求值；另测外部导航、重定向和弹窗协议。测试只替代系统浏览器调用，不实际打开外网。渲染器路由阻断不等于整台 Windows 断网，不能代替后续完整离线验收。

```powershell
node desktop/scripts/measure-startup.cjs
```

测量脚本执行三个新资料目录的首次启动及各一次重开，最后一次空闲两分钟后记录整棵进程树的工作集和数量，随后核对本次 PID 均退出。结果和虚构截图位于 `desktop/test-results`。首次启动测量不清系统磁盘缓存，不能当成重启操作系统后的冷缓存测试；开发机的环境隔离也不能代替干净 Windows 普通用户实机验收。

`.github/workflows/desktop.yml` 在 Windows 上检查 Java 文件库、桌面 lint、类型、行为、开发与打包程序联动，再保存三种验证包、校验和和报告七天。它只有仓库读取权限，不发布版本。原 Ubuntu/MySQL/浏览器 CI 保留，桌面 H2 结果不能代替原数据库回归。

完整的 Windows 普通用户、断网、安装卸载、升级和真实供应商测试尚需后续阶段完成。跨库备份与桌面文件保存恢复已在随机隔离库验收，系统对话框人工操作仍留在实机验收。首个公开版本须使用通过验收的同一提交和附件哈希，完成候选包确认后再发布。

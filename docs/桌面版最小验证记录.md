# Windows 桌面版最小验证记录

日期：2026-10-16。版本：`1.1.0-beta.1`。这是第 0 阶段工程验证记录，不是完整桌面版发布验收；尚未建立公开 Release。

## 已验证行为

- 默认网站基线为提交 `44effa1`，408 项 Java 测试包含 23 项真实 MySQL 隔离库测试，全部通过。
- 新增桌面文件库、初始化、认证与退出测试后，`mvn -q -Pdesktop clean verify` 共 428 项，零失败、零错误、零跳过，仍包含 23 项真实 MySQL。网站默认编译另外通过。
- H2 空目录执行桌面 Flyway 并由 JPA `validate` 核对；中文空格目录、关闭后重新打开、结构损坏拒绝启动均有文件库测试。不改变原 MySQL 历史迁移。
- 真实 JAR 通过标准输入接收本次控制凭据和版本；就绪时报告随机回环端口。匿名访问拒绝，一次性引导生成本地会话，业务写入仍校验 CSRF。错误版本拒绝就绪；正常关闭与父管道断开均退出。
- 受管会话模拟闲置三十一分钟后仍可使用；未受管网站同样闲置仍按原规则失效。
- 真实 HTTP 在途写入先刷新数据库但不提交，再请求退出。原十秒预算会提前取消排空并关闭连接池；修复后超过十六秒仍等待，释放后 HTTP 200、事务提交，再关闭。重开文件库可找到虚构记录。后端保留二十四小时有限兜底，壳十五秒后可由用户选择继续等待或强退。
- Electron 真实窗口在 PATH 只有 System32、未传开发凭据的环境启动，新增虚构作品，关闭后重开仍存在。页面不能调用 Node，定位权限检查返回拒绝。
- 已复现并修复草稿取消退出后后端先被关闭的问题。真实窗口取消退出后原文保留、后端仍返回 200，并可实际保存感想。
- 桌面 11 项 Node 行为测试、ESLint 和 TypeScript 检查通过。原网站 Node 174 项中 173 项通过，1 项未启用真实演示而跳过；真实演示及浏览器完整回归继续由原 Ubuntu CI 执行，不能把跳过计为已执行。

全部写入使用本轮创建的随机隔离资料或测试数据库及虚构文本，未向自用资料导入样例。开发工作区原有六项 `target` 内容单独备份保护，不纳入源码提交。

## 首次运行与资源测量

测试环境：Windows 11 家庭版中文，版本 `10.0.26100`，AMD Ryzen 9 7940HX，约 32 GB 内存。Electron 44.7.2、Temurin JRE 17.0.20.1+1、H2 2.2.224；运行时来源和 SHA256 在 `desktop/runtime-windows-x64.json`，完整 Java 许可随包保留。

通过 `node desktop/scripts/measure-startup.cjs` 在三个新临时资料目录测量，每个目录启动两次，最后一次空闲两分钟后采样。计时从启动进程至首页输入框可用，包含本次 Playwright 检查开销；未清系统磁盘缓存，不等同于操作系统冷启动。

| 项目 | 三次结果 |
|---|---|
| 新资料首次打开 | 14.632 / 14.147 / 14.804 秒 |
| 同资料再次打开 | 13.455 / 15.443 / 14.277 秒 |

空闲采样工作集合计 `966,787,072` 字节，约 **922 MiB**，共 7 个进程，包含测试启动辅助 `cmd.exe`、Electron 主进程及其子进程、Java 和隐藏的控制台宿主。它是各进程工作集相加，可能重复计算共享页，不代表私有物理内存；Java 本次约 499 MiB。关闭后逐轮核对本次进程 PID 均已消失。启动耗时和资源仍有优化空间，不对其他机器承诺相同结果。

首次本地打包的免安装 exe 约 170.44 MiB、安装版约 170.65 MiB、zip 约 240.35 MiB。后续修复和 CI 包以各自产物及 `SHA256SUMS.txt` 为准；这些数字只记录当次测量，不是发布附件哈希。

## 仍未满足的发布条件

- 当前是在开发机清理运行环境入口后验证，未取得没有 Java、Node、MySQL 的干净 Windows 普通用户实机；Windows Sandbox 在本机不可用。Windows 10 兼容也未验证。
- 前端四个 CDN 脚本由测试映射到锁定 npm 资源，未改成成品本地资源，因此尚不能承诺断网首次启动。
- AI 设置与系统密钥存储、完整事务与跨库备份对照、自动备份、升级和卸载保留资料、CSP 整理及完整桌面操作仍按后续阶段实施。
- 性能测量使用开发启动器和空资料；真实分发包、较大资料集、中文安装路径、缩放与干净系统必须补测。
- 当前无项目代码签名，不根据打包日志中的签名步骤宣称程序已签名；实际防护软件和 SmartScreen 行为须针对受测附件记录。
- Windows CI 与原网站 CI 只有在推送后才能核对。CI 通过也不能替代干净系统和首个候选包确认。

下一阶段先验证文件数据库的原业务行为、真实并发和 MySQL→H2 完整备份往返；这些工作使用隔离资料推进，不把未验收包交给用户存放唯一数据。

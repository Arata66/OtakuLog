# 桌面版身份与本地资源验收

验收日期：2026-10-17。范围为 Windows 桌面计划第2阶段；为建立同源脚本策略，提前完成第4阶段的四个前端脚本本地化和桌面 Service Worker 隔离。全部业务写入使用随机隔离资料与虚构文本，不使用自用库，不调用真实 AI。完整断网、密钥设置、升级备份和干净系统发布仍待后续阶段。

## 身份与历史兼容

只有同时启用 desktop profile 与 `app.desktop.managed=true` 才免登录，并输出受管桌面标志、隐藏退出登录入口。401 提示重启程序，不跳转网站登录页。业务 Cookie、Principal、CSRF 和原有归属检查保留；网站与非受管 desktop 仍走表单登录。

`DesktopIdentityHttpTest` 通过真实 bootstrap Cookie、页面令牌和回环假上游验证收藏预览与确认、推荐展示与反馈、防重结果；外来身份的预览或批次不能写入。缺会话、缺 CSRF 均拒绝。恢复保留历史 owner，不能用桌面身份重新执行旧请求键，拒绝后完整备份不变。

## 事件与脚本边界

模板和八个业务脚本共198处行内事件已迁为集中监听。动作来自固定 Map，参数使用转义后的 JSON 数组，不按任意全局名称查找函数，也不执行字符串。保留表单取消默认、嵌套添加停止传播、遮罩关闭和图片失败占位；原有草稿、版本冲突和请求防重继续生效。

Markdown 使用 DOMPurify 禁用 data 属性；事件及图片监听另排除两类用户原文区域，用户内容即使伪造已知应用命令也不能触发写入。浏览器新增交互覆盖引号名称、伪造命令、反复开关面板、图片失败、分组及年报遮罩。

仅受管桌面启用 CSP：脚本仅同源，事件属性和动态求值禁用，禁止嵌入页面、对象、base 和工作线程。样式保留已有行内兼容，图片允许 HTTPS、data 与必要 blob。未关闭 webSecurity，也未允许任意脚本源。网站登录链不加入这套桌面 CSP。

## 随包资源与缓存

| 资源 | 固定版本 |
|---|---|
| Chart.js | 4.4.1 |
| Sortable | 1.15.0 |
| marked | 12.0.2 |
| DOMPurify | 3.4.16 |

`scripts/vendor-assets.cjs` 核对声明、锁文件和安装版本，复制明确脚本及许可，生成逐文件 SHA256 清单。`--check` 逐字比较，不信任已有清单、不自动修复。测试覆盖篡改、缺许可、版本不一致及 Windows 换行转换；`.gitattributes` 仅禁止 vendor 目录的换行转换。两个 CI 都在安装锁定依赖后核验。

两份上游许可的原始 CRLF 与行末空格另外使用精确文件属性兼容 Git 空白检查，不改许可原文。独立 Git 仓库行为测试验证许可可暂存且检出后字节不变，第一方脚本的行末空格仍会失败。

网站和桌面都使用应用自身的四个脚本；浏览器与 Electron 测试不再提供 CDN 替代映射。桌面使用系统字体，网站保留可选 Google Fonts。桌面启动只清理专用会话的 Service Worker 与 CacheStorage，不清 Cookie、localStorage 或业务库；清理期间退出不会再打开窗口和后端。网站继续注册静态缓存。

## 真实窗口与控制通道

Electron 使用新临时资料、阻断渲染器外部资源，实际核对四个本地脚本，再执行新增、进度、感想、Markdown 和图表。安全探针由同源脚本标签自然执行，验证行内脚本、事件属性、外部脚本、eval 和 Function 被拒绝；不把 CDP 直接求值当作 CSP 证据。

窗口拒绝外部导航与同源地址转向外部的重定向；弹窗仅将 HTTPS 交给系统浏览器，测试只记录调用、不真正打开外网。重定向缺口先由真实 Electron 失败复现，再添加 `will-redirect` 拦截。

曾有一次重启停留启动页：后端已就绪，但 Node fetch 拒绝随机端口6679；同版 Electron 页面可访问该端口。固定回环控制传输改用 Node HTTP，保留五秒总时限、不跟随重定向、错误状态拒绝和多条 Set-Cookie。真实 HTTP 回归验证受限端口、请求凭据、重定向零跟随、服务错误、断连和总超时关闭；没有扩大页面权限或仅增加等待时间。

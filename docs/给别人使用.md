# 给别人使用

当前版本是单人资料库：一个实例内的作品、感想、画像、推荐条件及备份共享同一份数据。登录与批次权限保护不等于每人资料隔离。不能直接让多位朋友登录现有自用实例后声称各有独立空间。

目前优先实施 Windows 独立桌面版：每人在自己的电脑保存资料，免注册登录，AI 可选且自备密钥。最小窗口、本地文件库和三种内部验证包已有实现；尚未公开发布，不能把当前验证包当成完成全部兼容与恢复验收的日常版本。实际进度与命令见[桌面版开发与验收](桌面版开发与验收.md)。

## 先按使用方式选择

| 使用方式 | 路线 | 需要补齐 |
|---|---|---|
| 少数朋友各自记录自己的番，主要使用Windows | Electron＋内置Java＋H2文件库，提供免安装、安装版与zip | 完整业务兼容、离线、AI设置、备份升级和干净Windows实机验收 |
| 大家只打开一个网址，手机也随时可用，每人资料独立 | 服务器网站 | 用户账户、全部业务数据与备份权限隔离、HTTPS、运维备份及生产容器验收 |
| 只展示公开作品与虚构演示，不让访问者记录私人数据 | 独立演示实例 | 匿名只读或临时演示权限、数据重置方案；不要连接自用数据库 |

如果目标是先找几位朋友试用各自的记录功能，建议先做每人独立的本地分发，保留现在的单人模型。这能减少新增多用户权限体系的范围；代价是手机不能随时访问同一份本地数据，需要各人电脑运行和自行备份。若手机随时使用是主要目标，服务器路线更合适，账户隔离应先完成。

## exe需要解决的实际问题

桌面版采用 Electron 独立窗口，随包携带 Java 17 和原有 Spring Boot，不要求最终用户安装开发环境。它复用现有页面和业务服务，主进程负责启动、会话引导、窗口与退出，Java 服务使用独立的桌面文件数据库配置。

网站模式继续使用 MySQL；桌面 profile 使用 H2 文件库和独立 Flyway 基线，保持 JPA `validate`。空库迁移与重开持久化已测试，全部业务事务、并发和 MySQL→H2 完整备份对照仍需逐项验收，不能只凭驱动启动成功判断兼容。

默认资料保存在 `%LOCALAPPDATA%\OtakuLog\`，与程序分离。免安装表示下载即可运行，复制 exe 不会自动带走个人资料；跨电脑通过完整备份迁移，AI 密钥需要重新配置。发布前仍需在没有开发环境的干净 Windows 中验证首次启动、端口冲突、退出、升级、安装卸载和 v6 备份往返。

## 服务器需要解决的实际问题

仓库已有Dockerfile与Compose配置，MySQL卷保留数据，应用等待数据库健康后启动。单服务器Compose部署是官方支持的方式，生产环境仍需调整配置，见[Docker官方生产部署说明](https://docs.docker.com/compose/how-tos/production/)。本项目容器实际构建、健康检查与卷重启尚未验收；本地MySQL及CI通过不替代这些检查。

开始时先使用独立测试实例、独立库和虚构资料，按[部署验收记录](superpowers/plans/2026-10-08-可复现部署.md)完成容器验证。若提供多人独立记录，之后为作品、感想、观点、外部收藏、推荐条件、反馈和备份恢复增加用户归属与权限，并验证跨用户访问被拒绝。AI凭据及额度、导入批次、删除和WebDAV备份也须明确归属，不能只新增登录表。

正式提供访问前，设置独立凭据、HTTPS和定期备份，完成从备份恢复到独立实例的演练。费用取决于地区、配置、域名和用量，尚未选购或估价；选定路线后再核对实际报价。生产实例与自用预览分开，不迁移或公开当前私人资料。

## 与已有网站共用服务器

如果已有博客或其他网站，可以让同一台服务器的Nginx按域名分流：原网站继续使用原域名，OtakuLog使用独立子域名，转发到内部应用端口。静态博客的线上服务只需读取构建产物；是否能再运行Java与MySQL，需要结合整机资源和实际负载确认。

| 项目 | 部署时核对 |
|---|---|
| 访问入口 | 优先使用独立子域名。当前前端与登录使用根路径，挂到已有网站的子路径需要额外适配，不能只添加一条转发规则 |
| 应用端口 | 由宿主机Nginx代理时，仅向本机发布应用端口。当前Compose的`${APP_PORT:-8080}:8080`未限制监听地址，部署配置需改为`127.0.0.1:${APP_PORT:-8080}:8080` |
| 数据库 | 当前Compose未向宿主机发布MySQL端口。保留独立的数据卷、凭据和备份，不把自用数据库作为公开试用库 |
| 资源与费用 | 检查可用内存、磁盘余量及CPU负载，再用虚构资料验证启动、收藏导入和备份时的资源占用。少量访问也有常驻服务开销；变更配置前核对账户权益和实际费用 |
| 上线验证 | 除OtakuLog的登录、HTTPS和备份恢复外，也确认原网站仍可正常访问 |

上表是部署准备要求，仓库尚未提供经过实机验收的共用服务器配置。多个域名分流只解决访问入口；多人独立记录仍须先补齐账户和全部资料权限隔离。

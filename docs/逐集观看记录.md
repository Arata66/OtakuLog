# 逐集观看记录与日期补录

登录后点击番剧名称，在详情的“观看记录”区域查看。每页 20 集，覆盖当前进度内的各集和已有的进度外历史记录。手机日期输入保持至少44像素高，取消核对、草稿重载及双窗口冲突流程见[浏览器核心回归](浏览器核心回归.md)。

## 日期与来源

| 提示 | 含义 |
|------|------|
| 观看时记录 | 使用下一集或开始观看时生成的记录 |
| 手动补录 | 手动标记完成时补齐，或主动保存、核对过的逐集记录 |
| 导入补录 | 旧格式导入时补齐的记录 |
| 历史来源不明 | LEGACY 数据可能包含旧版估算，日期需用户核对 |
| 日期未知 | 已有记录，但不知道具体观看日期 |
| 缺少记录 | 当前进度包含该集，但没有逐集记录 |

日期输入不会预填今天。不确定就留空，不要用开播日期或完成日期推测。填写实际日期后点击该行“保存”；历史来源不明的行使用“核对并保存”，会弹出确认。只核对所点击的一集，其他行不会自动升级来源。

保存日期变更或确认 LEGACY 后，该集来源变为 MANUAL。日期相同且来源已经明确时，保留原来源和更新时间。清空已有日期会要求确认，记录仍然保留，日期存为未知，不进入年度观看量。

只允许保存今天及之前、1000 年起的日期。补录不会改变当前集数、追番状态、观看起始日或完成日期；不能为进度外尚无记录的集新增记录。已有的进度外历史可继续校正。

## 冲突与未保存输入

其他窗口进退集、恢复备份或修改同一集后，原弹窗可能过期。保存会比较原记录快照，冲突时提示重新加载，并保留输入供核对，不自动重试覆盖。重新加载或翻页会放弃草稿，有未保存日期时会先确认。

保存某一行后，其他行修改过的日期输入会保留；没有修改的行使用最新查询结果。写入成功但刷新失败时会明确提示，重新加载后才能继续保存。关闭或切换详情不会让旧响应覆盖新作品。

进退集成功后，详情同步进度、状态和完成日期；无日期草稿时刷新记录，有草稿时保留输入并提示重新加载核对。退集导致当前页超出范围时回到最后一页。

保存后刷新观看热力图与日常入口的最近观看日期；年度报告下次打开重新获取。核对有日期的 LEGACY 记录后，该集从历史参考转为对应日期年份的明确观看量。完整备份保留日期、来源和审计时间，详见[年度统计口径](年度统计口径.md)与[备份与恢复](备份与恢复.md)。

## 接口

需要登录；PUT 还需要 CSRF 令牌。GET 为只读，不生成或升级记录。

- `GET /api/anime/{id}/episodes?page=0&size=20`：page 非负、size 为 1–50；返回 animeId、currentEpisode、page、size、totalRows、entries。
- 每条 entry 包含 episodeNumber、recorded、recordId、watchedDate、source、updatedAt；日期和审计时间可以为空，缺记录的 ID、来源和时间均为空。
- `PUT /api/anime/{id}/episodes/{episodeNumber}`：请求必须显式包含 watchedDate（ISO 日期或 null）及 expected（原 GET 返回的完整 entry），不要丢失时间精度或自行重建快照。
- 成功返回 200；非法参数 400、作品不存在 404、快照冲突 409。冲突后需重新读取并核对；成功后重新 GET 获取新的审计时间。

逐集补录与日常入口均不新增表或 Flyway 迁移。当前 Service Worker 静态缓存版本为 v16，与数据库迁移 V9 是不同版本体系。
